核心功能亮点
三层中间件生命周期管控
@wrap_tool_call 工具调用中间件：全局拦截监听所有工具调用，自定义业务标记写入运行时上下文；
@before_model 模型前置中间件：大模型调用前自动打印对话状态、消息日志，方便调试与链路追踪；
@dynamic_prompt 动态提示词中间件：根据上下文标记自动切换系统提示词，无需硬编码绑定固定 Prompt。
Runtime 运行时上下文机制
基于单次对话请求隔离的全局共享字典 runtime.context；
支持中间件间跨环节传参、自定义业务标记（如报告模式标识）；
单次会话结束自动销毁，用户 / 会话之间数据隔离，无残留污染。
动态场景 Prompt 自动切换通过工具中间件写入业务标记，动态提示词中间件读取标记，自动切换普通对话提示词 / 报告生成专用提示词，实现业务场景无感切换，解耦提示词与主业务逻辑。
Agent 流式对话输出封装 execute_stream 流式接口，基于 agent.stream 增量返回会话状态，解析消息片段通过 yield 实现打字机式流式输出，适配前端实时展示场景。
工具与模型调用链路闭环完整链路：用户请求 → 初始化上下文默认值 → 模型首次思考 → 调用工具 → 工具中间件修改上下文标记 → 模型二次加载动态提示词 → 生成业务专属回答 → 流式返回前端。

技术栈
Python
大模型 Agent 框架（自定义中间件装饰器体系）
Runtime 运行时上下文、状态机流转
流式输出 Generator /yield
动态 Prompt 调度、工具调用拦截

项目架构流程
接口入口初始化会话上下文，默认注入业务标识默认值；
模型调用前触发日志中间件，记录对话消息数量与最新消息内容；
触发工具调用时，工具中间件拦截并写入场景标记到 runtime.context；
动态提示词中间件读取上下文标记，自动匹配加载对应系统提示词；
大模型依据动态 Prompt 生成回答，通过循环解析状态字典 + yield 逐段流式返回。

适用场景
大模型多场景智能体（普通问答、报告生成、业务工单等）
需要动态切换系统提示词的业务系统
需全局监听工具调用、做日志审计与流程管控的 Agent 应用
前后端流式 AI 对话服务快速落地
